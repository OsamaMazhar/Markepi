# Phase 13 — UI Design Contract

> Visual and interaction contract for batch processing. Generated by gsd-ui-researcher.
>
> **Platform:** iOS 18 native (SwiftUI). No web framework. Apple HIG + SF Symbols design system.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (iOS Native — SwiftUI) |
| Preset | not applicable |
| Component library | SwiftUI native (no third-party) |
| Icon library | SF Symbols (Apple system) |
| Font | SF system font (dynamic type supported) |

**Design authority:** Apple Human Interface Guidelines (HIG) for iOS. The app already follows HIG patterns established in v1.0/v1.1/Phase 12. Phase 13 extends existing UI components rather than introducing a new design language.

### Visual Hierarchy

**Primary focal point:** "Watermark All" button (`.borderedProminent`, 56pt height, centered in toolbar) — the main action driving the batch workflow.

**Secondary elements:** Thumbnail strip with override dot indicators — shows batch composition at a glance. Preview area with current item — shows what will be watermarked.

**During batch processing:** Progress overlay becomes the primary focal point — determinate progress bar, "X of Y" count, ETA. Cancel button is secondary.

## Spacing Scale

Declared values (points, consistent with existing codebase patterns):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Inline gaps between icon+label |
| sm | 8pt | LazyHStack thumbnail spacing, compact element gaps |
| md | 16pt | Default horizontal padding, form row spacing |
| lg | 20pt | VStack section spacing (ControlsView `spacing: 20`) |
| xl | 24pt | Section-to-section gaps, toolbar padding |
| 2xl | 44pt | **Minimum touch target** (Apple HIG) — buttons, icons |
| 3xl | 56pt | Large CTA buttons (picker, "Watermark All") |

Exceptions:
- **44pt minimum touch target** (Apple HIG requirement) for all interactive elements: `BatchItemDetailSheet` tap targets, Cancel button, thumbnail cells, "Reset" buttons
- Existing thumbnail cells are 60×60pt (already exceeds 44pt minimum)
- Existing share button height is 50pt (exceeds 44pt minimum)

## Typography

SF system font with dynamic type support throughout. Existing app uses these roles consistently:

| Role | Size | Weight | Usage |
|------|------|--------|-------|
| Caption | 12pt (`.caption`) | Semibold (600) | Progress percentage, ETA text, dot indicator labels |
| Body | 17pt (`.body`) | Regular (400) | Description text, summary copy, alert messages |
| Heading | 22pt (`.title3`) | Semibold (600) | Sheet titles, notification titles, section headers |
| Display | 28pt (`.title`) | Semibold (600) | Primary empty-state heading, batch completion overlay |

All sizes support Dynamic Type scaling. `.monospacedDigit()` modifier applied to all numeric progress displays (percentage, count, ETA) — consistent with existing ControlsView pattern (line 163).

## Color

Apple semantic colors. Consistent with existing ControlsView, ThumbnailStripView, and TemplateListView patterns:

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `.systemBackground` | Main `ContentView` background, `BatchItemDetailSheet` background |
| Secondary (30%) | `.ultraThinMaterial` | Thumbnail strip background (existing), progress overlay background, notification surfaces |
| Accent (10%) | `.accentColor` (system blue) | Selection border on current thumbnail (existing), active override dot indicator, navigation links |
| Destructive | `.red` | Cancel button in progress overlay, "Reset All Overrides" destructive confirmation |
| Success | `.green` | "Ready to Share" state (existing pattern), batch completion checkmark |
| Progress | `.blue` | Progress bar fill (existing `.tint(.blue)` pattern from ControlsView line 158) |
| Warning | `.orange` | Failed items in batch summary detail |

**Accent reserved for:** current-thumbnail selection ring (existing), per-item override dot indicator (new), and interactive navigation links only. **Never** used for decorative elements, background fills, or non-interactive text.

**New UI surfaces inherit these tokens:**
- `BatchItemDetailSheet`: `.systemBackground` background, `.accentColor` for "Reset to Batch Config" button
- Progress overlay: `.ultraThinMaterial` background with `.blue` progress bar
- Override dot indicator: `.accentColor` fill on thumbnail cells

## Interaction Contracts

### 1. Batch Initiation
- **Trigger:** User taps "Watermark All" button when `photos.count > 1`
- **Pre-condition:** `renderingState == .idle`, at least 2 items in `photos` array
- **Transition:** `renderingState` → `.batchProcessing(current: 0, total: photos.count, eta: nil)`
- **UI:** Preview area transitions to `BatchProgressOverlay` (`.ultraThinMaterial` background with progress bar, counts, ETA, Cancel button)

### 2. Per-Item Override (BATC-05)
- **Trigger:** User taps a thumbnail cell in `ThumbnailStripView`
- **Transition:** `.sheet` presents `BatchItemDetailSheet` with that item's current config (shared config merged with any existing per-item overrides from the delta dict)
- **UI:** Full `ControlsView` equivalent scoped to the tapped item. "Reset to Batch Config" button at top. "Done" button to dismiss.
- **Indicator:** After override is set, a small `.accentColor` dot (6pt diameter) appears on the thumbnail cell's top-right corner
- **Accessibility:** Dot reads "Custom watermark applied" via `.accessibilityLabel`

### 3. Drag-to-Reorder Thumbnails
- **Trigger:** User long-presses and drags a thumbnail cell
- **Behavior:** `.onMove` reorders `photos` array. Cosmetic only — does not affect processing order or output.
- **Visual:** Standard SwiftUI list reorder animation (cell lifts, other cells slide)

### 4. Batch Processing Progress (BATC-02)
- **Progress bar:** Determinate `.linear` progress view, spans full width of overlay, `.tint(.blue)`
- **Count label:** "`current` of `total`" centered above progress bar, `.font(.caption.weight(.semibold))`
- **ETA label:** "ETA: `{minutes}` min" below count, `.font(.caption2).foregroundStyle(.secondary)`
- **Cancel button:** Below ETA, red-tinted `.bordered` button "Stop Processing" at 50pt height
- **Cancel behavior:** `Task.checkCancellation()` at each item boundary. Current item finishes. Remaining skipped. Temp files cleaned up. State → `.idle`.
- **Cancel confirmation:** `.confirmationDialog` "Cancel batch processing?" with destructive confirm

### 5. Batch Error Resilience (BATC-03)
- **Behavior:** When a single item fails, it's added to `BatchProcessingResult.failures` dict. Processing continues to next item.
- **Progress bar:** Continues advancing. No interruption of the progress overlay.
- **At completion:** If any failures exist, summary alert shows mixed results. If all fail, alert shows all-failure message with retry option.

### 6. Batch Completion (BATC-04, BATC-06)
- **Transition:** `renderingState` → `.done`, preview area returns to normal `PreviewView`
- **Share sheet:** Automatically presents with `[URL]` array of all successful output files
- **Summary alert:** "Batch Complete — N of M processed. K failed." with "Show Details" for failure inspection
- **Notification:** If app backgrounded: `UNUserNotificationCenter` delivers "Batch Complete" notification. Tapping notification returns to app and opens share sheet.
- **Post-completion:** All items remain in thumbnail strip. User can adjust config and re-process.

### 7. Reset All Overrides (BATC-05)
- **Trigger:** User taps "Reset All Overrides" button (in toolbar or overlay when overrides exist)
- **Confirmation:** `.confirmationDialog` "Reset All Overrides?" with destructive confirm
- **Behavior:** Clears entire `[PhotoItem.ID: WatermarkConfiguration]` delta dict. All override dot indicators removed.
