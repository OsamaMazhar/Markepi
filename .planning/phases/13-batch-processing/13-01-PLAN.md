  <action>
    Create BatchProcessor.swift with a public actor BatchProcessor containing:

    Nested public struct BatchItem: Sendable:
    - id: UUID — maps to PhotoItem.id for failure tracking
    - sourceURL: URL — temp file URL of the media to process
    - mediaType: WatermarkEngine.MediaType — .photo, .video, .livePhoto, or .unknown
    - overrideConfig: WatermarkConfiguration? — nil means use sharedConfig; non-nil means use this config for this item

    Properties:
    - private let engine = WatermarkEngine.shared

    public typealias ProgressHandler = @Sendable (Int, Int, TimeInterval?) -> Void

    Primary method signature:
    public func process(items: [BatchItem], sharedConfig: WatermarkConfiguration, onProgress: ProgressHandler?) async -> BatchProcessingResult

    Implementation — SERIAL LOOP per CONTEXT.md (parallel processing explicitly out of scope):

    1. Record batchStartTime = Date()
    2. Initialize successes: [URL] = [], failures: [UUID: Error] = [:]
    3. For (index, item) in items.enumerated():
       a. try Task.checkCancellation() — checked at each item boundary; current item finishes, loop exits, temp files for unprocessed items are NOT created yet
       b. Determine config = item.overrideConfig ?? sharedConfig
       c. Switch on item.mediaType:
          - .video: await engine.processVideo(sourceURL: item.sourceURL, config: config, onProgress: { progress, eta in ... })
            After video export completes successfully: await Task.sleep(for: .milliseconds(500)) — 0.5s inter-export delay to prevent AVAssetExportSession hardware decoder exhaustion (STATE.md Pitfall #4)
          - .photo, .livePhoto, .unknown: await engine.process(sourceURL: item.sourceURL, config: config)
       d. On success: append result.url to successes, if nil url skip
       e. On error (any Error type including CancellationError outside the checkCancellation gate): append (item.id, error) to failures dict — do NOT throw, continue to next item per BATC-03
       f. Calculate per-item elapsed, ETA: let eta = perItemElapsed * Double(items.count - index - 1)
       g. Call onProgress?(index + 1, items.count, eta > 0 ? eta : nil) — fires on each item completion including failures
       h. Wrap synchronous work (steps d, f, g) in autoreleasepool { } to drain autoreleased objects from array mutations/String ops per STATE.md memory mandate
    4. Calculate duration = Date().timeIntervalSince(batchStartTime)
    5. Return BatchProcessingResult(successes: successes, failures: failures, duration: duration)

    Error handling rules:
    - CancellationError caught at checkCancellation: re-throw to exit loop
    - Any other error: add to failures, call onProgress, continue — never abort batch
    - If engine.process or engine.processVideo throws, the temp file for that failed item should be cleaned up via TempFileManager.cleanup(url:) before continuing

    Create BatchProcessorTests.swift with:
    - Test that a single photo item produces one success URL
    - Test that cancellation mid-batch (via Task.cancel) stops after current item and returns partial results
    - Test that a deliberately failing item (e.g., unsupported format URL) adds to failures but continues to next item
    - Test that progress callback fires correct (current, total) values at each item boundary
    - Test that duration is > 0 after a successful batch
  </action>
