<objective>
Create the EXIF token parsing and substitution system that lets users embed dynamic camera metadata in watermark text and frame attribution. Eight token types (`{camera_model}`, `{lens}`, `{aperture}`, `{focal_length}`, `{shutter_speed}`, `{iso}`, `{date}`, `{gps}`) are recognized, extracted from the source image's CGImageSource metadata dictionary, formatted per D-09 through D-11, and substituted into text strings before rendering.

Purpose: Per D-06/D-07, tokens enable "Shot on iPhone 16 Pro, f/1.78, 24mm" style attribution without requiring the user to manually type camera specs. The token system must be format-agnostic (per D-07: works for HEIC, JPEG, PNG, and future ProRAW/DNG).

Output: A stateless `EXIFTokenParser` utility struct, integration into both `TextWatermarkRenderer` (new metadata-aware overload) and `WhiteFrameRenderer` (token substitution on `customAttributionText`), engine wiring in `buildFilterGraph()`, and comprehensive tests.
</objective>

**Create `EXIFTokenParser.swift`** at `Packages/WatermarkCore/Sources/WatermarkCore/Utilities/EXIFTokenParser.swift`.

Follow the `DeviceMetadataProvider` struct pattern exactly (public struct, static methods only, no stored state).
Imports: `import Foundation` and `import ImageIO` (same as DeviceMetadataProvider).

Implement the RESEARCH.md Pattern 1 design with these concrete identifiers:

**Dictionary key constants** (matching DeviceMetadataProvider lines 20–24 pattern):
```swift
private static let exifDictKey = "{Exif}"       // kCGImagePropertyExifDictionary → String
private static let tiffDictKey = "{TIFF}"       // kCGImagePropertyTIFFDictionary → String
private static let gpsDictKey = "{GPS}"         // kCGImagePropertyGPSDictionary → String
```

**Token enum** (8 cases matching D-06): `case camera_model, lens, aperture, focal_length, shutter_speed, iso, date, gps`

**Public API:** `public static func substitute(_ text: String, metadata: [String: Any]) -> String`

Implementation: iterate over `Token.allCases`, for each token whose `"{\(token.rawValue)}"` pattern appears in `text`, call a private `value(for:metadata:)` resolver and replace. Return modified text.

**Token value resolvers** (private static methods):
- `camera_model`: `metadata["{TIFF}"] → ["Model"]` as String. Fallback: "--"
- `lens`: `metadata["{Exif}"] → ["LensModel"]` as String. Fallback: "--"
- `aperture`: `metadata["{Exif}"] → ["FNumber"]` as Double → format as `String(format: "f/%.1f", value)`. Fallback: "--"
- `focal_length`: `metadata["{Exif}"] → ["FocalLength"]` as Double → format as `String(format: "%.0fmm", value)`. Fallback: "--"
- `shutter_speed`: `metadata["{Exif}"] → ["ShutterSpeedValue"]` as Double → convert APEX: `exposureTime = pow(2.0, -apexValue)`. If < 1.0: `"1/\(Int(round(1.0/exposureTime)))"`. Else: `String(format: "%.1fs", exposureTime)`. Fallback: "--" (Pitfall 5 prevention: always convert APEX to seconds, never use raw APEX value)
- `iso`: `metadata["{Exif}"] → ["ISOSpeedRatings"]`. Handle both `[Int]` (take first) and `Int`. Format as `"ISO \(value)"`. Fallback: "--" (Pitfall 4: handle both types per research A4)
- `date`: `metadata["{Exif}"] → ["DateTimeOriginal"]` as String (fallback: DateTimeDigitized → DateTime). Parse with `DateFormatter` format `"yyyy:MM:dd HH:mm:ss"`, output with locale-aware `.short` dateStyle per D-10. Fallback: "--"
- `gps`: `metadata["{GPS}"] → ["Latitude", "LatitudeRef", "Longitude", "LongitudeRef"]`. Lat/Lon as Double, ref as String. Format: `String(format: "%.4f° %@, %.4f° %@", abs(lat), latRef, abs(lon), lonRef)` per D-09. Fallback: "--" (Open Question #4: use String keys "Latitude", "LatitudeRef" matching DeviceMetadataProvider pattern — these are the post-convertCFDictionary representations)

**Important implementation notes:**
- Substitution order: iterate tokens and replace each `{token}` pattern independently — the 8 tokens have no substring overlap (Pitfall 4 prevention per RESEARCH.md lines 549–557)
- Do NOT use regex or NSRegularExpression — simple `String.replacingOccurrences(of: "{\(token.rawValue)}", with: value)` is sufficient for 8 fixed tokens (per RESEARCH.md "Don't Hand-Roll" table)

```swift
/// Renders a text watermark with EXIF token substitution applied to the text string.
/// Token substitution happens BEFORE NSAttributedString creation per D-07.
/// - Parameters:
///   - config: Text watermark configuration (text may contain {tokens})
///   - metadata: Source image metadata dictionary (for token resolution via EXIFTokenParser)
/// - Returns: A CIImage with token-substituted text rendered at the configured position
public static func render(config: TextWatermarkInput, metadata: [String: Any]) -> CIImage {
    let substitutedText = EXIFTokenParser.substitute(config.text, metadata: metadata)
    let substitutedConfig = TextWatermarkInput(
        text: substitutedText,
        fontSize: config.fontSize,
        color: config.color,
        opacity: config.opacity
    )
    return render(config: substitutedConfig)
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User text input → EXIFTokenParser | Untrusted user-authored text containing `{token}` patterns enters the parser. Must handle arbitrary input without crash or injection. |
| CGImageSource metadata → Token formatter | Metadata values from CGImageSource are assumed well-formed but may be missing — parser must handle nil/missing fields per D-08. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02 | Denial of Service | EXIFTokenParser.substitute() | mitigate | Iterates over 8 fixed Token enum cases — bounded loop. No regex backtracking. O(8 × n) where n = input length. Cannot be exploited via crafted token strings. |
| T-05-03 | Information Disclosure | EXIFTokenParser (date, gps tokens) | accept | EXIF metadata is already present in the source file; rendering it as text in the watermark does not expose new information. User controls which tokens they include. |
| T-05-04 | Spoofing | EXIFTokenParser (missing fields) | mitigate | D-08: missing fields always render as "--" — never raw token literal, never empty string. Prevents spoofed attribution in watermarks. |
| T-05-SC | Tampering | npm/pip/cargo | accept | No package installs — all Apple system frameworks. |
</threat_model>
