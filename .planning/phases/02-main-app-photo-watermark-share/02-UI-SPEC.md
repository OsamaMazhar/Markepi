## 1. Screen Architecture

### Single-Screen App

The main app is a **single screen** with zero navigation stack — there is no NavigationStack, no sheet navigation beyond system dialogs (PhotosPicker, share sheet, alerts). The entire user journey happens on one view.

```
┌─────────────────────────────────────────┐
│              ContentView (Root)          │
│  ┌─────────────────────────────────────┐ │
│  │       Preview Area (60% height)     │ │

│  │  │  Watermarked Image Preview    │  │ │
│  │  │  + MagnifyGesture (pinch)     │  │ │
│  │  │  + Scale percentage overlay   │  │ │
│  │  └───────────────────────────────┘  │ │
```

## 2. Layout Specification

### 60/40 Split (D-09)

The screen is divided via `GeometryReader` in a `VStack(spacing: 0)`:

| Zone | Height | Content |
|------|--------|---------|
| Preview Area | 60% of safe area height | Watermarked photo preview + thumbnail strip |
| Divider | 1px | `.separator` color, full width |
| Controls Area | 40% of safe area height | Scrollable control panel |

**Spacing within layout:**

| Element | Spacing | Notes |
|---------|---------|-------|
| VStack gap (preview ↔ controls) | 0px | Divider provides visual separation |
| Preview padding | 0px edges | Image fills available width with `.aspectRatio(contentMode: .fit)` |
| Controls horizontal padding | 16px (SwiftUI `.padding(.horizontal)`) | Standard iOS content inset |
| Control section vertical gap | 20px | Between control groups |
| Control label-to-input gap | 8px | Label above each input |
| Thumbnail strip height | 72px | Fixed height, positioned at bottom of preview area |
| Thumbnail size | 60×60px | With 8px corner radius |
| Thumbnail inter-item spacing | 8px | LazyHStack |

### Safe Area Handling

- Preview uses `edgesIgnoringSafeArea(.top)` for edge-to-edge image display
- Controls respect bottom safe area (home indicator) — content inset of 20px minimum
- Center "+" picker button respects all safe areas — positioned using `.position(x:y:)` relative to geometry center
- Thumbnail strip respects horizontal safe areas with 16px inset

## 3. Component Inventory

### 3.1 PhotosPicker Trigger Button

| State | Appearance | Behavior |
|-------|-----------|----------|
| **Empty (no photos)** | Large pill button, gradient fill (system blue → system indigo), SF Symbol `photo.on.rectangle.angled` + "Add Photos" label, centered on screen | Tapping opens PhotosPicker with `.photosPicker(isPresented:)`. This button IS the picker trigger. |
| **Has Photos** | Compact pill button, positioned top-trailing of preview area, SF Symbol `plus.rectangle.on.rectangle` only, no label | Tapping opens PhotosPicker to add more photos |

**Auto-open behavior (D-01):** On first launch, `showPicker = true` is set in `.onAppear`. The PhotosPicker system sheet animates in immediately. If the user cancels without selecting, the center picker button is shown.

**Dimensions:**
- Empty state: 200×56px pill, 28px corner radius
- Has-photos state: 44×44px circle, 14px corner radius

**Visual spec:**
- Background: `.ultraThinMaterial` with system blue gradient overlay
- Icon size: 24pt SF Symbol (weight: regular)
- Label font: `.body` weight `.semibold`, white text

### 3.2 Watermarked Preview View

| State | Appearance | Behavior |
|-------|-----------|----------|
| **No photo selected** | Empty preview zone showing the center picker button (same as 3.1 empty state) | — |
| **Photo selected, no preview yet** | Low-res thumbnail from PhotosPickerItem, `.aspectRatio(contentMode: .fit)`, may show loading shimmer | The initial thumbnail is displayed while the engine renders the first preview |
| **Preview ready** | Full preview image via `Image(uiImage: previewUIImage)`, `.resizable()`, `.aspectRatio(contentMode: .fit)`, `.drawingGroup()` for Metal acceleration | Watermark is visible at selected position + scale |
| **Preview generating** | Previous preview remains with `.overlay(ProgressView())` centered, dimmed slightly (opacity 0.6) | Full-screen blur is NOT used — prev preview stays visible |
| **Preview error** | Previous preview remains (if any), error shown via alert (D-17) | See Error Alert component |

**Gesture:** `MagnifyGesture` applied to the Image view. Scale effect is real-time on the view (GPU). Engine scale config updates only in `.onEnded`.

**Scale overlay:** During pinch, a capsule label appears at top-trailing showing current scale percentage (e.g., "15%"). Uses `.ultraThinMaterial` background, `.caption` font, 4px corner radius, 4px padding.

### 3.3 Thumbnail Strip

| State | Appearance | Behavior |
|-------|-----------|----------|
| **0 photos** | Hidden (height: 0) | Not rendered |
| **1 photo** | Hidden (height: 0) | D-13: shown only when 2+ photos |
| **2–4 photos** | `LazyHStack` centered in strip, no scrolling | Tap to switch current photo |
| **5+ photos** | `LazyHStack` in `ScrollView(.horizontal)`, scrollable | `ScrollViewReader` auto-scrolls to current index via `.onChange(of: currentIndex)` |
| **Loading thumbnail** | 60×60 placeholder with `ProgressView()` and `.fill` background `Color(.systemGray6)` | — |
| **Thumbnail ready** | 60×60 `Image(uiImage:)` with `.aspectRatio(contentMode: .fill)`, 8px corner radius | — |
| **Current photo** | 3px accent border (`Color.accent`) around thumbnail, `.animation(.easeInOut)` | Tap to jump |

**Dimensions:**
- Strip height: 72px total (60px thumbnails + 12px padding)
- Thumbnail: 60×60px, corner radius 8px
- Current indicator: 3px border, accent color
- Inter-item: 8px

### 3.4 Text Watermark Input

| State | Appearance | Behavior |
|-------|-----------|----------|
| **Empty** | `TextField` with placeholder "Watermark text…", `.textFieldStyle(.roundedBorder)`, multi-line | Cursor blinks. No watermark rendered (or invisible) until text entered. |
| **Has text** | Shows entered text in the field | Triggers debounced preview update (350ms after last keystroke). Multiple lines via `\.newline`. |
| **Excessively long (>500 chars)** | Text truncated server-side before passing to engine. No visual change in UI. | Validation: max 500 characters. Engine would error on overly long text anyway. |
| **Disabled** | Grayed out if no photo selected | Interaction prevented |

**Dimensions:**
- Minimum height: 80px (accommodates ~3 lines of text at body size)
- Uses `TextEditor` for true multi-line behavior, or `TextField` with `axis: .vertical` (iOS 16+)
- Font: `.body` (17px Dynamic Type)

### 3.5 Position Grid

A 3×3 grid of position preset buttons.

| Element | Appearance | Behavior |
|---------|-----------|----------|
| Grid layout | `LazyVGrid(columns: 3)` with 8px spacing | 3 columns × 3 rows |
| Button | 40×40px square, `.bordered` style, position label as abbreviated text (TL, TC, TR, ML, C, MR, BL, BC, BR) | Tapping sets the watermark position for the active layer |
| Selected | Filled accent color background, white SF Symbol `checkmark` overlay | Only one button selected at a time |
| Unselected | `.bordered` style, system gray border, label text in `.secondary` | — |
| Disabled | Grayed out at 0.4 opacity if no watermark layer exists | — |

**Accessibility:** Full position names as `.accessibilityLabel()` (e.g., "Top Left", "Top Center", "Top Right").

### 3.6 Scale Stepper (Accessibility Fallback — D-08, D-18)

| State | Appearance | Behavior |
|-------|-----------|----------|
| **Idle** | Label "Scale: 15%" + `Stepper` with ±5% increments | Tapping increments/decrements scale by 0.05. Long-press for continuous adjustment. |
| **Disabled** | Grayed out if no watermark layer | — |
| **At min (1%)** | "-" button disabled, stepper visually dimmed | Can't go below 0.01 |
| **At max (90%)** | "+" button disabled, stepper visually dimmed | Can't go above 0.90 |

**Dimensions:** Standard SwiftUI `Stepper`. Label: `.body` font, `.secondary` color.

### 3.7 Logo / Image Watermark Picker (D-04)

| State | Appearance | Behavior |
|-------|-----------|----------|
| **No logo** | Button "Add Logo" with SF Symbol `photo.badge.plus` | Tapping shows `.confirmationDialog` with "From Photos" and "From Files" options |
| **Logo selected** | Shows logo filename + thumbnail (44×44), "Remove" link next to it | X button per D-12 to remove the logo layer |
| **Picker active** | System PhotosPicker or DocumentPicker sheet is presented | — |
| **Invalid file** | Alert: "This file format is not supported. Please select a PNG image." | Only PNG accepted (D-03 from Phase 1) |

**Confirmation dialog:**
- Title: "Add Logo Watermark"
- Option 1: "From Photos" → opens PhotosPicker filtered to `.images`
- Option 2: "From Files" → opens `.fileImporter` for `.png`
- Cancel button

### 3.8 Layer List (D-12)

| State | Appearance | Behavior |
|-------|-----------|----------|
| **No layers** | Not shown (empty state) | — |
| **1 layer** | Single row: layer type icon + description + X button | Tapping X removes the layer. Tapping row selects it for editing. |
| **Multiple layers** | `List` of rows with reorder handles (via `.onMove`) | Per D-01 from Phase 1: ordered layer stack (bottom → top). X button per row removes that specific layer. |

**Row layout:**
- Leading: SF Symbol indicating type: `textformat` (text) or `photo` (image/logo)
- Center: Description — text watermark shows first 20 chars, logo shows filename
- Trailing: X button (SF Symbol `xmark.circle.fill`), red tint, 44×44px tap target

**Removal behavior:** Tap X → immediate removal with `.animation(.easeOut)`. If this was the only layer, layer list hides. Preview updates (debounced).

### 3.9 White Frame Toggle

| State | Appearance | Behavior |
|-------|-----------|----------|
| **Off** | `Toggle("White Frame", isOn: $config.whiteFrame.isEnabled)` | Toggle is off, frame not rendered |
| **On** | Toggle on, preview shows white frame | `WhiteFrameConfig(isEnabled: true)` passed to engine |
| **Disabled** | Grayed out if no photo selected | — |

**Visual:** Standard SwiftUI `Toggle`. Label: `.body`. No additional controls for v1 (frame width and metadata toggles are engine defaults per Phase 1).

### 3.10 Share Button (D-06, D-07)

| State | Appearance | Behavior |
|-------|-----------|----------|
| **Idle (no render)** | Filled accent color pill button, SF Symbol `square.and.arrow.up` + "Share", full width, 50px height | Tapping starts full-res render. Transitions to "Rendering" state. |
| **Rendering** | Same pill, SF Symbol replaced with `ProgressView()` (circular spinner, `.controlSize(.regular)`), label changes to "Rendering…", button disabled | Engine runs `.process()` in background. Non-blocking — rest of UI remains interactive. |
| **Render complete** | Pill animates to green tint with checkmark SF Symbol `checkmark.circle.fill` + "Ready to Share". Short scale pulse animation (1.05× → 1.0× over 300ms, easeOut). | Button re-enabled. User must tap again to confirm and open share sheet. |
| **Share sheet active** | Button returns to idle state. Share sheet is presented via `.sheet()`. | See 3.11 Share Sheet Bridge. |
| **Error** | Returns to idle state. Alert presented via `.alert()` with error message. | See 3.13 Error Alert. |
| **Disabled** | Grayed out at 0.4 opacity. "Select a photo to share" as label if no photo. | — |

**Animation spec:**
- Idle → Rendering: Crossfade label to spinner, 200ms
- Rendering → Complete: Spinner crossfade to checkmark + green tint shift + scale pulse, 300ms total
- Complete → Idle (after share dismiss): Instant reset

**Two-tap flow detail:**
1. **Tap 1 (Share):** Button enters "Rendering" state → engine renders full-res → preview updates to show full-res result → button enters "Ready to Share" state
2. **Tap 2 (Confirm):** User sees full-res watermarked preview, confirms by tapping → share sheet opens

### 3.11 Share Sheet Bridge

| Element | Details |
|---------|---------|
| Type | `UIViewControllerRepresentable` wrapping `UIActivityViewController` |
| Presentation | `.sheet(isPresented: $viewModel.showShareSheet)` |
| Activity items | `[tempFileURL]` — the output from `ProcessingResult.url` |
| Excluded types | `.saveToCameraRoll` (per core product value) |
| Dismiss callback | `completionWithItemsHandler` fires `TempFileManager.cleanup(url:)` on all dismiss paths (share, save, cancel) |

**Why not `ShareLink`:** `ShareLink` presents immediately on tap and has no completion callback. The two-tap flow requires programmatic control.

### 3.12 Cancel Multi-Photo Alert (D-15)

| Element | Value |
|---------|-------|
| Title | "Discard Changes?" |
| Message | "All unsaved watermark configurations will be lost." |
| Destructive button | "Discard" — resets state, re-opens picker |
| Cancel button | "Keep Editing" — dismisses alert |
| Presentation trigger | Set `showCancelAlert = true` via cancel button in toolbar/nav area |

### 3.13 Error Alert (D-17)

| Element | Value |
|---------|-------|
| Title | "Rendering Error" |
| Message | `error.localizedDescription` from the engine |
| Dismiss button | "OK" — clears `errorMessage` and `showError` |
| Presentation trigger | Set `showError = true` when `renderingState = .error(_)` |

**Error types that can surface:**
- Engine pipeline errors (Phase 1 `PipelineError`)
- File I/O errors
- Memory pressure warnings
- Invalid watermark configuration

## 4. Interaction Design

### 4.1 Pinch-to-Resize (D-08)

| Aspect | Spec |
|--------|------|
| Gesture | `MagnifyGesture()` |
| Live effect | `scaleEffect(effectiveScale)` on the SwiftUI `Image` view (GPU-accelerated, no re-render) |
| Gesture state | `@GestureState private var pinchScale: CGFloat = 1.0` for in-flight, `@State private var committedScale: CGFloat` for final |
| Scale range | Clamped to 0.01–0.90 (matching engine `WatermarkLayer` scale range) |
| Engine update | Only in `.onEnded` — sets `config.watermarks[layerIndex].scale = clampedScale`, triggers debounced preview re-render |
| Percentage overlay | Shows during pinch (when `pinchScale != 1.0`), displays `Int(effectiveScale * 100)` + "%" |
| Accessibility | Stepper with ±5% increments always visible in controls (D-18). VoiceOver set `\.accessibilityZoomAction` on preview for pinch simulation. |

### 4.2 Debounce Timing (D-05)

| Aspect | Spec |
|--------|------|
| Mechanism | `.task(id: previewIdentifier)` with `Task.sleep` |
| Window | 350ms (midpoint of 300-500ms range from D-05) |
| Identifier | Computed property combining current index + config hash: `"\(currentIndex)-\(configHash)"` |
| Cancellation | Automatic — SwiftUI cancels previous `.task` when `id` changes; `Task.sleep` throws `CancellationError` |

**Example:**
```swift
.task(id: viewModel.previewIdentifier) {
    guard viewModel.currentPhoto != nil else { return }
    try? await Task.sleep(for: .milliseconds(350))
    await viewModel.generatePreview()
}
```

### 4.3 Tap Targets

| Element | Minimum size | Notes |
|---------|-------------|-------|
| Buttons (share, picker, position grid) | 44×44px | Apple HIG minimum |
| Layer removal (X button) | 44×44px | Redundant with HIG minimum — explicit because adjacent to small text |
| Thumbnails | 60×60px | Well above minimum, easy tap |
| Stepper (±) buttons | 44×44px (system default) | — |
| Toggle switch | 51×31px (system default) | — |

### 4.4 Animation Specs

| Transition | Duration | Curve | Notes |
|-----------|----------|-------|-------|
| Share button: idle → rendering | 200ms | `.easeInOut` | Crossfade label to spinner |
| Share button: rendering → complete | 300ms | `.easeOut` | Spinner → checkmark + green + scale pulse |
| Scale pulse on render complete | 300ms | `.easeOut` | `scaleEffect(1.05)` → `scaleEffect(1.0)` |
| Layer removal | 250ms | `.easeOut` | Row fades + slides out |
| Thumbnail current-index change | 250ms | `.easeInOut` | Border highlight + ScrollViewReader scroll |
| Preview image update | 150ms | `.easeInOut` | Crossfade between old and new preview |
| Picker trigger button appearance | 300ms | `.spring(response: 0.3, dampingFraction: 0.7)` | Empty → has-photos transition |

### 4.5 Scroll Behavior

- Controls area scrolls vertically (`.scrollIndicators(.hidden)`) when controls overflow the 40% height
- Thumbnail strip scrolls horizontally (`.scrollIndicators(.hidden)`) when 5+ photos
- No gesture conflicts: preview has `MagnifyGesture`, thumbnails have `ScrollView(.horizontal)`, controls have `ScrollView(.vertical)` — all in separate view hierarchies

## 5. Visual Design Tokens

### 5.1 Typography (SF System, Dynamic Type)

| Role | SwiftUI Text Style | Base Size | Weight | Line Height | Usage |
|------|-------------------|-----------|--------|-------------|-------|
| Display | `.largeTitle` | 34px | `.bold` | 1.2 | Only for empty-state "Add Photos" prompt (if used) |

**Dynamic Type:** All text styles use `\.dynamicTypeSize` range `.xSmall...\.xxxLarge` (full system range). Layout must accommodate:

| Dynamic Type | Body Size | Impact |
|-------------|-----------|--------|
| xSmall | 14px | Controls area shrinks slightly |
| Large (default) | 17px | Reference size |
| xxxLarge | 28px | Controls area may need more vertical space via ScrollView |

**Font weight usage:**
- `.regular` (400) — Body text, input fields, status labels
- `.semibold` (600) — Section headers, button labels, current-thumbnail number

The app uses iOS system colors that automatically adapt to light and dark mode. No custom hex colors.

## 6. State Transitions

### 6.1 App Launch → First Photo Selection

```
[App Launch]
    │
    ▼
┌──────────────────────┐
│ EMPTY STATE           │
│ Center "+" button     │
│ Auto-open PhotosPicker│
└──────┬───────────────┘
       │ User selects photo(s)
       ▼
┌──────────────────────┐
│ LOADING               │
│ Thumbnails generated  │
│ (async, per-photo)    │
└──────┬───────────────┘
       │ All thumbnails loaded
       ▼
┌──────────────────────┐
│ CONFIGURING           │
│ Preview rendered      │
│ Controls active       │
│ (debounced updates)   │
└──────────────────────┘
```

### 6.2 Import → Configure → Preview → Share (Full Flow)

```
┌──────────────────────────────────────────────┐
│                  EMPTY STATE                  │
│  PhotosPicker auto-opens (D-01)              │
│  If cancelled: center "+" button shown        │
└────────────────────┬─────────────────────────┘
                     │ User selects 1–20 photos
                     ▼
┌──────────────────────────────────────────────┐
│                LOADING PHOTOS                 │
│  ┌──────────────────────────────────────┐    │
│  │ "Loading photos…"                    │    │
│  │ [ProgressView per item]              │    │
│  │ CGImageSource thumbnails generated   │    │
│  │ Temp copies created for engine input │    │
│  └──────────────────────────────────────┘    │
└────────────────────┬─────────────────────────┘
                     │ All photos loaded
                     ▼
```

### 7.2 Dynamic Type

- All text respects `\.dynamicTypeSize` from `.xSmall` to `.xxxLarge`
- Controls area uses `ScrollView` to accommodate large text without truncation
- Position grid buttons use `.label` rather than fixed text size — icons will scale
- Thumbnail labels (photo count) use `.caption` and wrap when needed

| Element | Default Animation | Reduced Motion Alternative |
|---------|------------------|---------------------------|

Implementation: Check `\.accessibilityReduceMotion` environment value. Wrap animations in `if !reduceMotion { withAnimation { ... } }`.

### 7.4 Pinch-to-Resize Accessibility Fallback (D-18)

- VoiceOver users: The stepper in controls always provides ±5% scale adjustment

- The stepper is always visible — not hidden behind any toggle or advanced menu

### 7.5 Minimum Contrast

All text/icon content meets WCAG AA minimum contrast (4.5:1 for normal text, 3:1 for large text) in both light and dark modes by using iOS system colors which are designed to meet these thresholds.

## 9. Edge Cases

### 9.1 Empty States

| Scenario | Behavior |
|----------|----------|
| First launch (no photos ever selected) | PhotosPicker auto-opens (D-01). Center "+" button shown as fallback if cancelled. |
| All photos removed (cancel confirmed) | Returns to center "+" picker button. PhotosPicker re-opens. |
| No watermark text entered | Preview shows un-watermarked photo. Engine still renders (valid config with empty text renders nothing). |
| No logo selected | Logo picker shows "Add Logo" label. No logo layer in config. |
| 0 layers in layer list | Layer list section hidden. |

### 9.2 Loading States

| Scenario | Indicator |
|----------|-----------|
| PhotosPicker items loading | Each thumbnail placeholder shows `ProgressView()` in its 60×60 frame |
| First preview generating | Low-res thumbnail shown + centered `ProgressView()` overlay + dim to 0.6 opacity |
| Subsequent preview updates (debounced) | Previous preview stays visible — no loading indicator (avoid flicker) |
| Full-res render in progress | Share button shows spinner; preview and controls remain interactive |
| Logo image loading from PhotosPicker | Brief `ProgressView()` replacing "Add Logo" button during `loadTransferable` |

### 9.3 Error States

| Scenario | User Experience |
|----------|----------------|
| Engine render fails (full-res) | Share button returns to idle. `.alert()` shows error message + "OK". User can adjust config and retry. |
| Engine render fails (preview) | Previous preview stays visible. `.alert()` shows error message. Auto-retry on next config change. |
| Invalid photo format | PhotosPicker filtered to `.images` — non-image selections are not possible. If engine can't process a loaded image, error alert shown. |
| Invalid logo format | After file/document picker dismiss, if non-PNG selected, alert: "Unsupported Format" / "Please select a PNG image file." |
| Temp file write failure | Error alert. User cannot share. Retry by adjusting config and re-rendering. |
| Memory pressure | System may terminate background tasks. App handles by showing error if render fails. Thumbnails use CGImageSource downsampling to prevent this. |

### 9.4 Cancel Flows

| Scenario | Behavior |
|----------|----------|
| Cancel from PhotosPicker (no selection) | Picker dismisses. Center "+" button remains. No state change. |
| Cancel from PhotosPicker (had previous photos) | Picker dismisses. Previous photos remain. User continues editing. |
| Cancel from multi-photo session | `.confirmationDialog` with "Discard" / "Keep Editing". If Discard: all photos cleared, picker re-opens. |
| Dismiss share sheet (via system cancel) | `completionWithItemsHandler` fires with `completed = false`. Temp file cleaned up. Share button returns to idle. |
| Navigate away from photo during render | Render continues in background. Result discarded if current photo changed before completion. No error — just stale result ignored. |

### 9.5 Memory & Performance

| Concern | Mitigation |
|---------|-----------|
| Large photo array in memory | Photos stored as source `URL` references + small (200px) thumbnails. Full-res loaded only during render, one at a time. |
| CIImage memory retention | Shared `CIContext` from Phase 1. CIImage objects are lazy — minimal memory until rendered. Preview rendered at 1200px max dimension. |
| Multiple rapid config changes | `.task(id:)` auto-cancels previous renders. Only the latest config is rendered. |
| Background termination | No persistence — user restarts from fresh picker on next launch. Acceptable for utility app. |

### 9.6 Orientation & Device Support

| Aspect | Spec |
|--------|------|
| Orientation | Portrait only (primary). Landscape supported but 60/40 split recalculates via `GeometryReader`. |
| Device sizing | iPhone SE (4.7") through iPhone 16 Pro Max (6.9") — all via Dynamic Type + GeometryReader. |
| iPad | Supported in Slide Over and full screen. 60/40 split expands proportionally. |
