<objective>
Build the video watermarking engine inside the WatermarkCore Swift Package. The engine uses AVFoundation's AVVideoCompositionCoreAnimationTool with a CALayer overlay hierarchy (per D-01) to composite watermark layers onto video frames during export. It preserves source HDR (Dolby Vision, HLG, HDR10 per D-09), color space, all audio tracks (D-11), and matches source format for output (D-04). Falls back to SDR with tone mapping and a warning when HDR cannot be preserved (D-10). Post-export validation inspects HDR metadata and audio track count (D-12).

Purpose: The video engine is the prerequisite for video watermarking anywhere — in the share extension (Plan 03) and in the Photos edit extension (Phase 4). It must be testable standalone from the command line (via Swift Testing framework) before any UI consumes it.

Output: Four new processing modules + modifications to WatermarkEngine, PipelineError, and ProcessingResult. The engine exposes `WatermarkEngine.shared.processVideo(sourceURL:config:) async throws -> ProcessingResult`.
</objective>

Step 1 — Load AVAsset and extract metadata:
- Create `AVURLAsset(url: sourceURL)`
- Load duration: `try await asset.load(.duration)`
- Create timeRange: `CMTimeRange(start: .zero, duration: duration)`
- Load video tracks: `try await asset.loadTracks(withMediaType: .video)`, guard at least one track exists → throw `PipelineError.videoTrackNotFound`

Step 2 — Build AVMutableComposition (D-11: audio passthrough):
- Create `AVMutableComposition()`
- Insert video track: add mutable track with `kCMPersistentTrackID_Invalid`, insert timeRange, set `preferredTransform` from source
- Insert ALL audio tracks (D-11): iterate `try await asset.loadTracks(withMediaType: .audio)`, for each: add mutable track + insert timeRange. NO mixdown. Preserve all channels.
- Verify audio track count: `composition.tracks(withMediaType: .audio).count == audioTracks.count` before proceeding (Pitfall 3 guard)

Step 3 — Determine video size accounting for portrait orientation:
- Get `naturalSize` and `preferredTransform` from video track
- If transform indicates portrait (`transform.isPortrait` — extend CGAffineTransform with a computed property): swap width/height
- Final `videoSize: CGSize`

Step 4 — Build CALayer hierarchy via VideoLayerBuilder (D-01, D-02):
- Call `VideoLayerBuilder.buildLayers(config: config, videoSize: videoSize) -> (parentLayer: CALayer, videoLayer: CALayer)`
- VideoLayerBuilder implementation:
  - `public struct VideoLayerBuilder` with `public static func buildLayers(config: WatermarkConfiguration, videoSize: CGSize) throws -> (parentLayer: CALayer, videoLayer: CALayer)`
  - Create `parentLayer = CALayer()`, frame = CGRect(origin: .zero, size: videoSize)
  - Create `videoLayer = CALayer()`, frame = parentLayer.bounds. Add as sublayer of parentLayer.
  - For each watermark layer in `config.watermarks` (D-02: all layer types):
    a. Render watermark as CGImage:
       - For `.text`: use `TextWatermarkRenderer.render(config:)` → CIImage → render via `CIContextProvider.shared.createCGImage(ciImage, from: extent, format: .RGBAh, colorSpace: nil)` → CGImage
       - For `.image`: use `ImageWatermarkRenderer.render(config:)` → same CGImage conversion
    b. Create watermark CALayer: `let wmLayer = CALayer()`, `wmLayer.contents = cgImage`, `wmLayer.contentsGravity = .resizeAspect`
    c. Scale: `let scaledExtent = CGSize(width: cgImage.width * watermark.scale, height: cgImage.height * watermark.scale)`
    d. Position using `PositionCalculator.position(for: watermark.position, watermarkExtent: scaledExtent, baseExtent: videoBounds, padding: config.padding)` — same coordinate math as photos
    e. Set wmLayer frame with CALayer coordinate system (origin top-left, y flipped from CIImage bottom-left): `wmLayer.frame = CGRect(origin: CGPoint(x: position.x, y: videoSize.height - position.y - scaledExtent.height), size: scaledExtent)`
    f. Add wmLayer as sublayer of parentLayer
  - For white frame (D-02): if `config.whiteFrame?.isEnabled == true`:
    a. Render white frame via `WhiteFrameRenderer.render(config:, baseExtent:, metadata:, scale:)` with empty metadata dict (videos don't have EXIF in the same way)
    b. Convert CIImage → CGImage → set as contents of a CALayer added below watermark layers
  - Return `(parentLayer, videoLayer)`

Step 5 — Detect HDR and configure AVVideoComposition (D-09, D-10):
- Check: `try await videoTrack.load(.hasMediaCharacteristic, with: .containsHDRVideo)` → `isHDR: Bool`
- Create `AVMutableVideoComposition()`
- Set `renderSize`, `frameDuration` (from `try await videoTrack.load(.minFrameDuration)`)
- Set `animationTool = AVVideoCompositionCoreAnimationTool(postProcessingAsVideoLayer: videoLayer, in: parentLayer)`
- If `isHDR == true` (D-09, D-10):
  - Extract source color properties from video track format descriptions:
    - Get `CMFormatDescription` from `try await videoTrack.load(.formatDescriptions)`
    - Extract `kCVImageBufferColorPrimariesKey`, `kCVImageBufferTransferFunctionKey`, `kCVImageBufferYCbCrMatrixKey` from `CMFormatDescriptionGetExtensions`
  - Set `videoComposition.colorPrimaries` = source primaries ?? `AVVideoColorPrimaries_ITU_R_2020`
  - Set `videoComposition.colorTransferFunction` = source transfer ?? `AVVideoTransferFunction_ITU_R_2100_HLG`
  - Set `videoComposition.colorYCbCrMatrix` = source matrix ?? `AVVideoYCbCrMatrix_ITU_R_2020`
  - Set CALayer color space: `parentLayer.colorspace = CGColorSpace(name: CGColorSpace.extendedLinearITU_R_2020)` (per Pitfall 1 mitigation — RESEARCH.md lines 549)
  - Track `var hdrPreservationAttempted = true` for post-export validation comparison
- If `isHDR == false`: leave color properties nil (system propagates SDR correctly)

Step 6 — Export with source format matching (D-04):
- Determine export preset: if `isHDR` → `AVAssetExportPresetHEVCHighestQuality`, else → `AVAssetExportPresetHighestQuality`
- Create `AVAssetExportSession(asset: composition, presetName: preset)`
- Guard non-nil → throw `PipelineError.videoExportSessionCreationFailed`
- Create output URL: `let outputURL = try TempFileManager.createTempFile(uti: "public.mpeg-4" as CFString)` (video output is always mp4/mov container)
- Set `exportSession.outputURL = outputURL`, `exportSession.videoComposition = videoComposition`, `exportSession.shouldOptimizeForNetworkUse = false` (quality over streaming per D-04)
- Match source outputFileType: use `await exportSession.determineCompatibleFileTypes()` to find compatible type matching source. If source is MOV → `.mov`, if MP4 → `.mp4`. Use source URL `typeIdentifier` resource value. Fallback to `.mp4`. Set `exportSession.outputFileType`.
- Run export: `await exportSession.export()`
- Check `exportSession.status == .completed` and `exportSession.error == nil`. On error: throw `PipelineError.videoExportFailed(exportSession.error)`.
- Track `var hdrPreserved = hdrPreservationAttempted` (will be validated post-export in ExportValidator, but note the attempt)

Step 7 — Post-export validation (D-12):
- Call `try await ExportValidator.validate(outputURL: outputURL, sourceAsset: asset, wasHDR: isHDR, hdrPreservationAttempted: hdrPreservationAttempted)`
- ExportValidator returns `ExportValidationResult` — log warnings via `os_log`
- If `wasHDR && !result.hdrPreserved`: D-10 fallback — log warning "HDR was flattened to SDR during watermark compositing". The warning is surfaced to the user via the ProcessingResult (added in Task 2).
- If `!result.audioTrackCountMatch`: log warning about audio track count mismatch

Step 8 — Return output URL:
- Return the temp file URL
