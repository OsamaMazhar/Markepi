**Important: This task modifies the file created in Task 1.** Add the following capabilities to InspectorSheetView.swift:

**1. Add `expandedHeight` parameter:**
Add `let expandedHeight: CGFloat` to the struct properties and init. This is the height of the expanded detent, computed by the parent (ContentView) as `geometry.size.height * 0.55`.

**2. Refine `sheetHeight` computed property:**
```
private var sheetHeight: CGFloat {
    let base = detent == .peek ? peekHeight : expandedHeight
    // Clamp: never below peekHeight, never more than expandedHeight + 50pt over-drag
    return max(peekHeight, min(expandedHeight + 50, base + dragOffset))
}
```
The +50pt ceiling allows a tactile over-drag feel before the snap.

**3. Implement `dragGesture` as a computed property:**
DragGesture attached ONLY to the indicator's `.gesture(dragGesture)` (already placed in Task 1).

**`.onChanged` handler:**
- Read `value.translation.height` — negative = dragging up (expanding), positive = dragging down (collapsing)
- `dragOffset = -value.translation.height` — invert so upward drag increases height
- No animation in this handler — raw tracking for smooth finger-follow
- No snap logic, no detent changes

**`.onEnded` handler:**
- Compute the midpoint between peekHeight and expandedHeight: `let midpoint = (peekHeight + expandedHeight) / 2`
- Compute current height: `let currentHeight = sheetHeight` (base + dragOffset at release point)
- If `currentHeight > midpoint`: set `detent = .expanded`
- Else: set `detent = .peek`
- Reset `dragOffset = 0` — critical per Pitfall 3, prevents stale offset carrying to next gesture
- Do NOT wrap in `withAnimation` — the `.animation(.spring(...), value: detent)` modifier on the sheet view (Task 1) automatically animates the detent change. The modifier also already handles Reduce Motion via `reduceMotion ? nil : .spring(...)`.

**4. Verifying D-15 (native nested scroll):**
No additional code needed. Since the DragGesture is attached ONLY to the drag indicator RoundedRectangle (not to the VStack or ControlsView), iOS gesture resolution naturally routes scroll gestures within ControlsView's ScrollView to the ScrollView, and drags on the indicator capsule to the DragGesture. This is structural separation, not programmatic coordination — per RESEARCH.md Pattern 2 implementation notes and Pitfall 2.

**Do NOT:**
- Use `withAnimation` in `.onEnded` — the `.animation()` modifier on the VStack handles it
- Use `DispatchQueue.main.async` for detent state changes — per Pitfall 3, must be synchronous
- Attach DragGesture to anything other than the indicator RoundedRectangle
- Use `lastDragPosition` accumulator pattern from RESEARCH — the simplified `dragOffset = -translation.height` approach is cleaner and avoids the Pitfall 3 glitch scenario
- Allow dragging below peek (D-04: not dismissible) — the `max(peekHeight, ...)` clamp enforces this
  </action>
