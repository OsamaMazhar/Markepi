    Both require `{ get set }` because the default `addLogoLayer` implementation writes to them. All 3 conformers already have these as stored `@Published`/observable properties — no conformer changes needed.

    **Change 2: Add protocol extension block AFTER the protocol closing brace (line 44)**

    Append the entire extension block after the existing protocol declaration. The extension must:
    - Be `extension WatermarkConfigurable { }` (no additional constraints — `@MainActor` and `AnyObject` are inherited from the protocol)
    - Use `// MARK: - Default Implementations` as the top-level marker
    - Group methods under `// MARK: Layer Management`, `// MARK: White Frame`, and `// MARK: Export Settings`

    The 8 defaults to implement, in order:

    **MARK: Layer Management**
    1. `addLogoLayer(pngData:)` — Validate via `CIImage(data: pngData)` guard (nil → set `errorMessage = "The selected image is not a valid PNG file."` and `showError = true`, return), then `ImageWatermarkInput(pngData:)` guard (nil → same error), then append `.image(input, position: .bottomRight, scale: 0.15, opacity: 1.0, isVisible: true)` and set `activeLayerIndex = config.watermarks.count - 1`. Requires `import CoreImage` for `CIImage(data:)`. (D-01, D-04)

    2. `addSignatureLayer(strokeData:inkColor:strokeWidth:)` — Empty body (default no-op per D-03). WatermarkViewModel overrides with its real PencilKit implementation; the two extension ViewModels drop their empty stubs and inherit this no-op.

    3. `removeLayer(at:)` — Guard `index >= 0, index < config.watermarks.count`, then `config.watermarks.remove(at: index)`, then adjust `activeLayerIndex = max(0, config.watermarks.count - 1)` if `activeLayerIndex >= config.watermarks.count`. (D-04)

    4. `updateLayerPosition(at:position:)` — Guard bounds, extract `let scale = config.watermarks[index].scale`, then 3-case switch on `config.watermarks[index]` (text/image/signature) reconstructing each case with `position: position` while preserving the input data, `scale: scale`, opacity, and isVisible. (D-04, D-05)

    5. `updateLayerScale(at:scale:)` — Guard bounds, clamp input via `min(max(scaleInput, 0.01), 0.90)`, extract `let position = config.watermarks[index].position`, then 3-case switch reconstructing each case with `scale: clamped` while preserving position, input data, opacity, and isVisible. (D-04, D-05)

    **MARK: White Frame**
    6. `toggleWhiteFrame()` — If `config.whiteFrame?.isEnabled == true` set `config.whiteFrame = nil`, otherwise set `config.whiteFrame = WhiteFrameConfig(isEnabled: true)`. (D-04)

    7. `whiteFrameEnabled: Bool` — Computed property with getter only: `config.whiteFrame?.isEnabled ?? false`. The protocol already declares `{ get }` — no setter needed. (D-02)

    **MARK: Export Settings**
    8. `outputFormat: OutputFormat` — Computed property with `get { config.outputFormat }` and `set { config.outputFormat = newValue }`. Satisfies the protocol's `{ get set }` requirement. (D-02)

    9. `outputQuality: Float` — Computed property with `get { config.outputQuality }` and `set { config.outputQuality = newValue }`. Satisfies the protocol's `{ get set }` requirement. (D-02)

    **Critical rules (from RESEARCH.md common pitfalls):**
    - Do NOT add `with(position:)`/`with(scale:)` helpers to WatermarkLayer (D-05)
    - Do NOT return a new config — mutate `self.config` directly (D-04, AnyObject reference semantics)
    - Do NOT change the protocol requirement signatures — only add the two error properties
    - The `import CoreImage` needed for `CIImage(data:)` in `addLogoLayer` is already imported at the top of WatermarkConfigurable.swift — no new imports needed (CoreImage is imported via `import WatermarkCore` which re-exports it, and `import Foundation` covers Data). If compilation fails on `CIImage`, add `import CoreImage` explicitly.
    - Do NOT add `import SwiftUI` — the existing `import SwiftUI` at line 2 is sufficient for the observable protocol context. The extension methods do not use any SwiftUI types directly.
