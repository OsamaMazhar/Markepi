    Create `MarkepiGlassModifier.swift`.

    **Struct: `MarkepiGlassModifier<S: Shape>`** (generic constraint over Shape, NOT existential `any Shape` — per RESEARCH.md Pitfall 4: the `glassEffect(in:)` API may reject existential types)

    Initializer parameters:
    - `shape: S` — the clipping shape for the glass effect (default: `Capsule()`)
    - `fallbackMaterial: Material` — the material used on iOS &lt; 26 (default: `.ultraThinMaterial`)
    - `isEnabled: Bool` — whether glass is active; when `false`, renders no background (default: `true`)

    `func body(content:)`:
    - Call `content.modify { view in ... }` (uses Task 1's utility extension)
    - Inside the transform: `if #available(iOS 26, *)` gate → `view.glassEffect(.regular, in: shape)` when `isEnabled` is true; else `view.background(fallbackMaterial, in: shape)`
    - D-03: NO `.tint()` call — the `.regular` variant handles system-adaptive tint (cool light, warm dark) automatically
    - When `isEnabled` is false (e.g., Reduce Transparency), render `content` unmodified with no background

    **View extension: `.markepiGlass(shape:fallbackMaterial:)`**
    - Convenience method on `View` that wraps `MarkepiGlassModifier`
    - Default `shape: Capsule = Capsule()`, `fallbackMaterial: Material = .ultraThinMaterial`
    - Mark as `public`

    **Important:** This modifier does NOT internally read `@Environment(\.accessibilityReduceTransparency)` — that decision belongs to the caller. The `isEnabled` parameter lets callers wire their own `reduceTransparency` check. Document in comments that callers should pass `isEnabled: !reduceTransparency` when wrapping accessibility-sensitive surfaces.

    Remove the `.gitkeep` file from `GlassEffect/` after creating the Swift file.
  </action>

## Trust Boundaries

No trust boundaries intersect this phase. All primitives are pure SwiftUI presentation-layer modifiers with no network calls, data persistence, file I/O, or user input processing.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Denial of Service (UX) | MarkepiTypography — Dynamic Type overflow | mitigate | Use system font styles (`.title3`, `.body`, `.caption`) which inherit automatic Dynamic Type scaling. No `minimumScaleFactor` or `lineLimit` constraints (D-15). Layout overflow handling belongs to consuming views (Phase 16-17). |
| T-15-02 | Information Disclosure (visual) | MarkepiGlassModifier — Reduce Transparency bypass | mitigate | Expose `isEnabled` parameter. Document that callers MUST wire `@Environment(\.accessibilityReduceTransparency)` and pass `isEnabled: !reduceTransparency`. The modifier does not enforce this internally to avoid hidden environment reads that complicate testing. |
| T-15-03 | Spoofing (UX) | MarkepiGlassModifier — iOS 18 fallback renders blank | accept | The `if #available(iOS 26, *)` gate with `.background(fallbackMaterial, in: shape)` fallback ensures a material background always renders on iOS 18. No scenario where glass produces a blank/transparent surface. Risk accepted as the mitigation is the fallback itself. |
| T-15-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this phase. All code uses Apple system frameworks (SwiftUI, Foundation). No external dependencies. |
</threat_model>
