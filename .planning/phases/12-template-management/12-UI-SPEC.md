# Phase 12 — UI Design Contract

> Visual and interaction contract for the Template Management phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Platform:** iOS native (SwiftUI) — no web/CSS tooling.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native SwiftUI) |
| Preset | not applicable |
| Component library | SwiftUI native (iOS 18) |
| Icon library | SF Symbols (system, no third-party) |
| Font | SF system (default iOS) |

**Source:** Existing codebase scan — all v1.0/v1.1 views use native SwiftUI components with SF Symbols and system semantic colors. No third-party UI libraries. No custom font families. No custom color palettes.

## Spacing Scale

Declared values (multiples of 4, derived from existing app conventions):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Tight inline gaps, icon-to-label spacing, divider padding |
| sm | 8pt | Compact element spacing, grid gaps, row internal gaps |
| md | 12pt | Row horizontal padding, overlay internal padding |
| lg | 16pt | Default content horizontal padding, default section gaps |
| xl | 20pt | Controls section spacing (`VStack(spacing: 20)` on `ControlsView`) |
| 2xl | 24pt | (available for new larger gaps — not currently used) |
| 3xl | 44pt | Icon touch target minimum (accessibility) |
| btn | 50pt | Primary action button height (matching existing Share button) |

**Source:** Existing codebase — `ControlsView` uses `VStack(spacing: 20)` and `.padding(.horizontal, 16)`. `LayerListView` uses `VStack(spacing: 8)` and `.padding(.horizontal, 12)` / `.padding(.vertical, 10)`. Touch targets at 44pt (icon) / 50pt (action button) from `ContentView` and `ControlsView`.

**Exceptions for this phase:**
- Template list row height: minimum 44pt touch target per row with 60pt preferred height to accommodate preview thumbnail
- Template preview thumbnail in list: 48×48pt, padded to 60pt row
- Sheet horizontal padding: 16pt (matching existing `.padding(.horizontal, 16)` pattern)

## Typography

All sizes in points (pt). All fonts are SF system (iOS dynamic type compatible).

| Role | Size | Weight | Line Height | SwiftUI Modifier |
|------|------|--------|-------------|-------------------|
| Body | 17pt | regular (400) | 1.5× (default) | `.font(.body)` |
| Subheadline | 15pt | regular (400) | ~1.4× | `.font(.subheadline)` |
| Label / Caption | 13pt | regular (400) | ~1.3× | `.font(.caption)` |
| Caption Bold | 13pt | medium (500) | ~1.3× | `.font(.caption.weight(.medium))` |
| Heading | 20pt | semibold (600) | 1.2× | `.font(.title3.weight(.semibold))` |

**Source:** Existing codebase — every view uses `.font(.title3.weight(.semibold))` for section labels, `.font(.body)` for content text, `.font(.caption)` for secondary labels. Only 2 weights used across the entire app: regular (400) and semibold (600). Medium (500) used sparingly for caption-level emphasis.

**Phase 12 additions:**
- Template name in list rows: `.font(.body)` (17pt regular)
- Default badge label: `.font(.caption2)` (12pt)
- Empty state heading: `.font(.title3.weight(.semibold))` (matching existing section heading pattern)
- Empty state body: `.font(.subheadline)` (matching existing "Preparing photo..." state)
- Save Template alert text field: `.font(.body)` (system default)

## Color

All colors use iOS semantic color system. No hardcoded hex values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | System background | Main screen background, sheet background, list background |
| Secondary (30%) | `.regularMaterial` | Card/group backgrounds, disabled button states, template list row backgrounds |
| Accent (10%) | `.accentColor` (system blue) | **Reserved for:** selected position grid cell, active template default badge, selected thumbnail border, toggle switch on-state, checkmark on selected row |
| Destructive | `.red` | **Reserved for:** swipe-to-delete row action, delete confirmation button, xmark-circle icons |
| Success | `.green` | **Reserved for:** "Ready to Share" button tint only |
| Warning | `.orange` | **Reserved for:** warning banners, retry button tint |

**Accent reserved for** (explicit list):
1. Position grid — selected position cell fill
2. Template default badge — star/filled-checkmark icon
3. Thumbnail strip — selected border stroke (3pt)
4. Toggle switches — `.tint(.accentColor)` on `Toggle`
5. Active template row — checkmark indicator when applied
6. Navigation bar buttons — SF Symbol icons

**Source:** Existing codebase — `Color.accentColor` used in `PositionGridView` for selected cell, `ThumbnailStripView` for border, `TextWatermarkInputView` and `ShareExtensionRootView` for preview. System semantic colors throughout (`Color(.separator)`, `.primary`, `.secondary`).

**Phase 12 additions:**
- Template list row background: `Color(.systemGroupedBackground)` for grouped list style
- Template default badge icon: `.accentColor` fill, foreground `.white`
- Swipe-to-delete action: `.red` background with white trash icon
- Empty state icon: `.secondary` foreground (matching existing empty/idle states)

## Interaction Patterns

### Template List Sheet

```
┌─────────────────────────────────────┐
│  ← Templates              Import (+)│  ← Navigation bar
├─────────────────────────────────────┤
│  [▊▊▊ No Templates Saved ▊▊▊]       │  ← Empty state (if 0 templates)
│  (icon)                              │
│  Configure your watermark then       │
│  tap Save Template...                │
│                                      │
│  ── OR (if templates exist) ──      │
│                                      │
│  ┌──────────────────────────────┐   │
│  │ [thumb]  Template Name  ★   │   │  ← TemplateRow (default has ★)
│  │  48×48   "Photo Credit"  ⋯  │   │     ⋯ = context menu trigger
│  └──────────────────────────────┘   │
│  ┌──────────────────────────────┐   │
│  │ [thumb]  Instagram Ready     │   │
│  │  48×48   "Footer only"    ⋯  │   │
│  └──────────────────────────────┘   │
│  ┌──────────────────────────────┐   │
│  │ [thumb]  Clean White Frame   │   │
│  │  48×48   "No text"        ⋯  │   │
│  └──────────────────────────────┘   │
│                                      │
└─────────────────────────────────────┘
```

**Interactions:**
- **Tap row** → Applies that template's config to the current ViewModel. Sheet dismisses. Provides haptic feedback (`.light` impact).
- **Swipe left** → Reveals red "Delete" action. Triggers confirmation alert.
- **Long press / tap ⋯** → Context menu with: Rename, Duplicate, Set as Default, Export, Delete
- **Pull to refresh** → Not needed (local data, no network)

### Context Menu (per row)

| Menu Item | Icon (SF Symbol) | Action |
|-----------|-------------------|--------|
| Apply | `checkmark` | Same as row tap — applies template, dismisses sheet |
| Rename | `pencil` | Presents alert with text field pre-filled with current name |
| Duplicate | `doc.on.doc` | Creates copy with " (copy)" suffix, inserts below original |
| Set as Default | `star` | Marks this template as the auto-apply default (TMPL-04) |
| Remove Default | `star.slash` | Shown instead of "Set as Default" when template IS default |
| Export | `square.and.arrow.up` | Opens ShareSheet with `.watermarktemplate` file |
| Delete | `trash` (`.red`) | Triggers confirmation alert |

**Note:** "Set as Default" and "Remove Default" are mutually exclusive — only one appears at a time based on the template's `isDefault` state. Only one template can be default at a time.

### Save Template Flow

```
User taps "Save Template" in ControlsView
        │
        ▼
┌──────────────────────────┐
│     Save Template        │
│                          │
│  Enter a name for this   │
│  template.               │
│                          │
│  ┌────────────────────┐  │
│  │ Template name      │  │  ← Text field, auto-focused
│  └────────────────────┘  │
│                          │
│      [Cancel]  [Save]    │  ← Save disabled when name empty
└──────────────────────────┘
```

**Validation:**
- Name cannot be empty → "Save" button disabled
- Name cannot duplicate an existing template → Alert: "A template named '[name]' already exists. Please choose a different name."
- Name max length: 50 characters → Text field truncates input
- On save success: brief haptic (`.notification(.success)`), sheet dismisses, template list updates
- On save failure: error alert with specific reason

### Template Preview Thumbnail (TMPL-06)

Each `TemplateRowView` renders a small 48×48pt preview showing the template's watermark config applied to the user's current media (if any media is loaded):

- **Media loaded:** Render a downsized preview using `CIContext.createCGImage` at 48×48pt with the template's `WatermarkConfiguration` applied. Cache result so scrolling is smooth. Show ProgressView while rendering.
- **No media loaded:** Show a placeholder thumbnail — the template's first text watermark snippet or a generic icon (SF Symbol: `doc.text`) on a `.systemGray6` background. Text label: "Import media to preview" above the list.
- **Rendering failure:** Show `.systemGray6` background with SF Symbol: `exclamationmark.triangle` (secondary foreground). Do not block the list — just skip the failed thumbnail.

### Swipe-to-Delete

Standard iOS `.onDelete` modifier on the `List` or `ForEach`:
- Swipe left reveals red "Delete" action with trash icon
- Tapping "Delete" triggers the confirmation alert
- After confirmation: row animates out, template removed from store
- If deleted template was the default: clear `isDefault` flag, no template auto-applies until user sets a new default

### Import Flow

Triggered from `TemplateListView` toolbar "Import" button:
- Opens `.fileImporter` filtered to `.watermarktemplate` UTI (or generic `.json` for fallback)
- On success: decode template, validate schema version, insert into store, animate row in
- On failure: alert "Could not import template. The file is invalid or uses an incompatible format."
- Duplicate name handling: auto-append " (imported)" suffix

### Export Flow

Triggered from context menu "Export":
- Serialize template to Codable JSON with `.watermarktemplate` filename
- Write to temp directory
- Present `ShareLink` or `UIActivityViewController` (wrapped in SwiftUI representable)
- After share completes: delete temp file

## States Coverage

### Template List States

| State | Visual | Interaction |
|-------|--------|-------------|
| **Empty** (0 templates) | Centered SF Symbol + heading + body text. "Import" toolbar button still available. | "Import" button opens file picker. "Save Template" in main view still works. |
| **Loading** (initial store read) | Full-list ProgressView with "Loading templates..." subheadline | Non-blocking — main UI still usable |
| **Populated** (≥1 template) | Scrollable List of `TemplateRowView` with ForEach. Default template has star badge and is pinned to top. | Tap to apply, swipe to delete, long-press for context menu, pull to refresh. |
| **Error** (store read failure) | Full-screen error: SF Symbol `exclamationmark.triangle`, "Could not load templates", "Retry" button | "Retry" reloads from App Group store |

### Template Row States

| State | Visual | Interaction |
|-------|--------|-------------|
| **Default** | Star icon (`.accentColor`) + "Default" label in `.caption2` | Context menu shows "Remove Default" |
| **Non-default** | No badge | Context menu shows "Set as Default" |
| **Preview rendering** | ProgressView inside 48×48 thumbnail frame | Row still tappable, preview may appear mid-scroll |
| **Preview failed** | Gray thumbnail + `exclamationmark.triangle` icon | Row still tappable, just no preview |
| **No media** | Placeholder thumbnail + "Import media" hint above list | Row still tappable (applies config, preview updates when media loaded) |

### Save Template States

| State | Visual | Interaction |
|-------|--------|-------------|
| **Name empty** | "Save" button disabled (grayed out) | Cannot proceed |
| **Name valid** | "Save" button enabled (`.accentColor`) | Tapping saves |
| **Duplicate name** | Error alert with "already exists" message | User must choose different name |
| **Saving** | ProgressView on Save button (if async) | Cancel button still active |
| **Saved** | Brief success haptic, sheet dismisses | Template appears in list |

### Default Auto-Apply (TMPL-04)

No new UI elements — this is a model-level behavior:
- When default template exists and new media is imported → ViewModel applies `defaultTemplate.config` to `self.config` automatically
- No visual indication on import (user sees the watermark appear on preview)
- If user manually changes config after auto-apply → their changes persist (auto-apply only fires on new import, not on every config change)
