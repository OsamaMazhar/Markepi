Give photographers a professional, on-device authorship protection workflow that preserves existing AI provenance, adds honest C2PA/IPTC rights records, and optionally evaluates invisible creator watermarking without making unsupported camera-authenticity claims.

## Phase 19: Provenance & Authorship Protection

**Goal:** Implement the professional provenance backbone for photo exports: classify source evidence conservatively, preserve existing AI provenance, add signed C2PA/IPTC rights records, expose user controls that cannot overclaim authenticity, and evaluate MIT/Apache invisible watermark tools for future or gated production use.

**Depends on:** v2.1 UI Redesign complete; existing image/video metadata preservation pipeline; Share Extension parity.

**Success Criteria** (what must be TRUE):

1. Every import receives a `SourceProvenanceReport` with one of five states: Verified Camera Capture, Marked AI / AI-Edited, User-Declared, Unknown Provenance, or Suspected AI.
2. Unmarked sources, including images from custom/open-source GenAI models that add no watermark, remain Unknown Provenance unless the user supplies a declaration.
3. Existing C2PA/JUMBF, XMP/IPTC Digital Source Type, EXIF/software metadata, HDR gain maps, and color profiles are preserved or carried forward as ingredients when Markepi exports.
4. Exports can include signed C2PA manifests and IPTC rights metadata using open-source CAI/C2PA tooling under Apache-2.0/MIT licensing.
5. The UI lets users control rights/protection/disclosure settings while blocking unsupported "verified camera" or "no AI used" labels.
6. Invisible watermarking is evaluated with open-source MIT candidates, with Adobe TrustMark as the primary prototype candidate and Microsoft InvisMark as research-only unless its iOS feasibility changes.
7. The export receipt clearly shows source state, evidence, user declarations, rights records, watermark status, and privacy actions.
8. The baseline remains fully on-device and offline.
9. Every production feature ships as iOS-native app/extension code. Desktop scripts, Python/PyTorch pipelines, and cloud services can exist only as evaluation tools, not as required product runtime.

## Open-Source Tooling Direction

| Tool | License | Milestone Role | Disposition |
|------|---------|----------------|-------------|
| `contentauth/c2pa-swift` | Apache-2.0 and MIT | C2PA read/verify/sign integration on iOS | Production candidate |
| `contentauth/c2pa-rs` | Apache-2.0 and MIT | Underlying C2PA engine wrapped by Swift bindings | Indirect dependency through c2pa-swift |
| `adobe/trustmark` | MIT | Invisible image watermark prototype and soft-binding candidate | Primary evaluation candidate |
| `microsoft/InvisMark` | MIT | Research comparison for invisible AI-provenance watermarking | Evaluation-only |

Commercial C2PA/provenance watermark vendors such as Digimarc and Imatag remain future paid integrations, not default dependencies for v2.2.

## iOS Implementation Position

The milestone assumes iOS implementation is practical for the production backbone:

- C2PA/IPTC provenance records through `contentauth/c2pa-swift`, ImageIO, and app/extension-safe Swift services.
- Metadata preservation through the existing `CGImageSource` / `CGImageDestination` photo path and AVFoundation video path.
- UI controls and receipts through shared SwiftUI components in WatermarkCore.
- Local/offline signing and configuration through app-group-safe storage.
- Secure Enclave-backed C2PA device signing on real iOS devices, with a local Keychain software fallback only for simulator/development or unavailable hardware.

Invisible watermarking is the conditional area. A provider can ship only if it runs locally inside the iOS app and Share Extension without a Python/PyTorch sidecar, external desktop tool, required cloud call, or incompatible model/package license.
