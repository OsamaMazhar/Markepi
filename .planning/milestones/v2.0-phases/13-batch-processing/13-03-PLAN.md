    Wrap the ForEach inside the LazyHStack (or replace the ScrollView structure) to support drag-to-reorder. The cleanest approach for iOS 18 SwiftUI: use a List with .onMove or add an @Environment(\.editMode) approach.

    Since this is a horizontal scroll view with LazyHStack, .onMove requires a ForEach on a collection that supports move operations. The existing ForEach already uses Array(photos.enumerated()) with id: \.element.id — this supports .onMove if the view hierarchy allows it.

    Add a helper view modifier or restructure:

    The simplest approach: wrap the content in a view that provides .onMove. SwiftUI's .onMove works on ForEach inside List, but for a ScrollView+LazyHStack, we need to use a different pattern.

    APPROACH: Use an @State var localPhotos: [PhotoItem] that mirrors photos, and provide an .onMove handler that reorders the ViewModel's photos array. Since drag-to-reorder is cosmetic only (per CONTEXT.md), we reorder localPhotos and sync back to ViewModel.

    Actually, the simpler approach: since ThumbnailStripView receives `photos` as a `let` constant (not binding), and the requirement says drag-to-reorder is cosmetic only with no effect on output, we should:

    1. Accept `photos` as `@Binding` instead of `let`, OR
    2. Add a `onReorder: ([PhotoItem]) -> Void` callback

    OPTION 2 is cleaner — add `onReorder: (([PhotoItem]) -> Void)? = nil` parameter. When non-nil, the view provides drag-to-reorder and calls this callback on reorder.

    For the actual drag implementation, since LazyHStack in ScrollView doesn't natively support .onMove, use the `.onDrag` / `.onDrop` API on each thumbnail cell, OR restructure to use a horizontal List. The most iOS-18-native approach is:

    Use a List with `.listStyle(.plain)` and a horizontal layout, OR:

    Use SwiftUI's `.onDrag` modifier on each thumbnail cell:
    - Each cell has .onDrag { NSItemProvider(object: photo.id.uuidString as NSString) }
    - The LazyHStack or its container has .onDrop with appropriate delegate

    SIMPLEST IMPLEMENTATION: Use a `List` with horizontal axis instead of ScrollView+LazyHStack, since List natively supports .onMove:

    List {
      ForEach(Array(photos.enumerated()), id: \.element.id) { index, photo in
        thumbnailCell(for: photo, index: index)
          .listRowInsets(EdgeInsets())
          .listRowBackground(Color.clear)
      }
      .onMove { source, destination in
        var reordered = photos
        reordered.move(fromOffsets: source, toOffset: destination)
        onReorder?(reordered)
      }
    }
    .listStyle(.plain)
    .scrollIndicators(.hidden)
    .environment(\.layoutDirection, .leftToRight)

    However, List is vertical by default. For horizontal, set the environment or use a ScrollView with manual drag handling.

    PRACTICAL APPROACH for iOS 18: Keep the existing ScrollView+LazyHStack structure and add .onDrag to each thumbnail cell. The parent container (ContentView) can handle the drop. This is the approach with the least structural change.

    Add to each thumbnail cell:

    And add an .onInsert modifier or .onDrop to the LazyHStack container. Since .onInsert is iOS 16+ and works with ForEach, use this:

    Add after the LazyHStack's padding modifiers:
    .onInsert(of: [.text]) { index, providers in
      // Read the dragged index from the provider and reorder
    }
