<objective>
Create the core data layer for template management: a versioned Codable `Template` model, a singleton `TemplateStore` with full CRUD and schema migration chain, and an App Group entitlements file for the main app target.

Purpose: Establish the foundation that all subsequent Phase 12 plans build on. The Template model wraps existing `WatermarkConfiguration` with metadata (name, default flag, creation date, schema version). TemplateStore persists `[Template]` as JSON in App Group UserDefaults — the same suite already used by AppGroupConfigSync. Schema versioning with MigrationChain ships on Day 0 to avoid 3-5× retrofitting cost (STATE.md blocker).

Output: `Template.swift`, `TemplateStore.swift`, `App.entitlements` — three new files enabling template persistence across all three targets.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Template import (file→store) | Untrusted `.watermarktemplate` file crosses from external source into App Group UserDefaults |
| Template export (store→file) | Internal template data crosses to external file — no validation needed (we control output) |
| UserDefaults (app↔extensions) | Template data shared across 3 process boundaries via App Group UserDefaults |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Denial of Service | TemplateStore.import() | mitigate | JSONDecoder has built-in nesting depth limits. Validate after decode: reject if schemaVersion > currentSchemaVersion, name > 50 chars, or config.watermarks.count > 20. Wrap decode in try? — on failure, reject import with user-facing error "Could not import template. The file is invalid or uses an incompatible format." |
| T-12-02 | Elevation of Privilege | TemplateStore.import() | mitigate | Imported template's isDefault is always forced to false regardless of file contents. Only explicit user action (context menu → "Set as Default") can mark a template as default. |
| T-12-03 | Denial of Service | TemplateStore (UserDefaults) | mitigate | ImageWatermarkInput.pngData stored inside template configs can be multi-MB. For v2.0, accept the size limitation as a known constraint (RESEARCH.md Pitfall 4). TemplateStore.save() validates total encoded [Template] size ≤ 500KB before writing to UserDefaults — if exceeded, returns a descriptive error. Full stripping/rehydration pattern (like PHAdjustmentData) deferred to v2.1 hardening. |
| T-12-04 | Information Disclosure | TemplateStore.delete() | mitigate | On template deletion, also clean up the associated thumbnail cache file at `cachesDirectory/template_thumbnails/thumb_{UUID}.png`. Additionally, on TemplateStore init, scan thumbnail cache directory and remove any files whose UUID does not match an existing template ID. |
| T-12-05 | Tampering | UserDefaults(suiteName:) | accept | UserDefaults across processes can be modified by any process with the App Group entitlement. All three targets are trusted (same developer, same app group). This is an inherent property of App Group storage — no additional mitigation possible. Accepted as low risk for a single-developer utility app. |
| T-12-SC | Tampering | npm/pip/cargo installs | n/a | No third-party packages are installed. All dependencies are Apple system frameworks. |
</threat_model>
