## Phase Details

### Phase 12: Template Management

**Goal:** Users can save, load, manage, and auto-apply watermark templates across all app entry points
**Requirements:** TMPL-01 through TMPL-06
**Plans:** 5 plans — Codable schema + store (01), inline UI + auto-apply (02), swipe-to-delete + rename + duplicate (03), default template (04), export/import (05)

### Phase 13: Batch Processing

**Goal:** Users can watermark multiple photos and videos in one operation with shared configuration, per-item adjustments, progress tracking, and error resilience
**Requirements:** BATC-01 through BATC-07
**Plans:** 3 plans — BatchProcessor actor + UI (01), per-item adjustment + progress (02), error resilience + notification (03)

### Phase 14: Process Hardening

**Goal:** GSD workflow tooling improvements that make phase execution more reliable and auditable
**Requirements:** PHRO-01, PHRO-02
**Plans:** 2 plans — VERIFICATION.md template + execute-plan integration (01), worktree precheck + timestamp fallback (02)

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| WatermarkConfiguration Codable for templates | Reuses existing schema; no new serialization format |
| Codable schema versioning with migration functions | Backward-compatible — old configs decode without crash |
| Serial batch processing (not parallel) | Memory safety — iOS jetsam kills parallel video exports |
| BatchProcessor actor in WatermarkCore | Shared across all 3 targets; single source of truth |
| Per-item override via delta dictionary | `[PhotoItem.ID: WatermarkConfiguration]` — nil = use shared |
| VERIFICATION.md populated during plan execution | Ensures no empty template left after plan completes |
| Worktree precheck before agent dispatch | Catches stale directories at the exact point of failure |
| Timestamp-suffixed fallback for occupied paths | `worktree-agent-{id}-{unix_timestamp}` — zero collision risk |
